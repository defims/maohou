# ADR 0105: Switch layers, point-level channels, and text strokes

* Status: accepted (2026-11-11)
* Relates to: ADR 0102 (property channels), ADR 0103 (folder compositing), ADR 0104 (bone
  system), ADR 0018 (variable-width strokes), ADR 0012 (text), ADR 0101 (Moho import), the
  Moho parity plan (fork plan › stage 5)

## Context

Stage 5 of the parity plan closes Moho's three remaining mid-size gaps: **switch layers**
(`SwitchLayer` with an animatable `switch_keys` ⟨ch:String⟩ selector that shows exactly one
variant at a time — mouth charts, limb sets), the **point-level family** (per-point position
channels, curve trim `start_percent`/`end_percent`, per-point widths and colours), and **text
enhancements** (Moho's text stroke; the derived `mesh_layer` geometry, which a bound text
needs because AniCraft's text outlines cannot ride bones).

The corpus's stage-5 fixtures were structural only (empty meshes, no selection), so the
acceptance gates needed working fixtures generated by Moho Pro 14.4 itself — the stage-4
method again: Lua menu scripts, saved as new files, Moho's own `FileRender` frames as the
pixel truth.

## Decision

1. **A switch is a layer kind, not a symbol.** `LayerKind::Switch` is a container (folder
   semantics: draws nothing, hides/locks/nests alike). Its variants are ordinary child
   layers addressed by name; `Layer.switch_to: Channel<String>` (the ADR 0102 channel model
   now over `String`, which always steps — a switch never half-shows two variants) keys the
   selection per frame. Evaluation filters every layer through
   `Timeline::shows_through_switches`: on the way up, the direct child of each enclosing
   switch must be the variant its selector names at the frame, and an unselected switch
   shows nothing. One uniform ancestor check covers switches inside folders, masks,
   symbols and each other — no per-pass bookkeeping.
2. **Animated points ride the shape, not a mesh copy.** `Shape.points: Vec<PointTrack>`
   names points by path-command order and carries a `Channel<Vec2>` each. Evaluation
   rebuilds the path per frame: tracked endpoints land on their sampled positions and the
   control points hanging off them follow rigidly (a moved point takes its handles along).
   A Moho point shared by several curves occurs at several path points — each occurrence
   gets a track sampling the same channel. Shapes without tracks keep their shared path:
   nothing animating costs nothing.
3. **Trim cuts each subpath by arc length; the fill goes while it cuts.** `Shape.trim`
   carries `start`/`end` fraction channels. Moho's untrimmed state is −0.1→1.1 (slightly
   past both ends); the raw values store and clamp at sample time, so that reads as no trim
   and an untouched shape never rebuilds. A trimmed subpath flattens and keeps the vertices
   between the fractions (a closed subpath wraps). The fill of a cut-open ring is not a
   shape, so a trimming shape draws its stroke.
4. **Point widths follow upstream ADR 0018; point colours only when they agree.** A shape
   whose points carry one non-default width multiplies the stroke width exactly (the
   gradients canvas's uniform 1.75×). Varying widths become a `WidthProfile` by arc
   fraction — exact on a single subpath, repeated per subpath (and reported) otherwise. A
   profile drawn from another layer's curve (`profile_curve_id`) has no slot yet and is
   counted. A uniform point colour replaces a solid fill and the stroke colour; varying or
   gradient cases are counted and drawn as authored.
5. **Text gains a stroke; bound text becomes geometry.** `TextBlock.stroke: Option<Stroke>`
   draws the glyph outlines stroked over the fill (Moho's text stroke; `linewidth` is an
   inch distance like a shape's). A text layer riding bones — a whole-layer binding or any
   bound saved point — imports its saved `mesh_layer` as real, bindable shapes instead of
   the text block, because a text block cannot follow bones; a plain text layer keeps the
   re-laid text and ignores the derived mesh, exactly as Moho regenerates it.
6. **Switch editing is a command namespace.** `switch.set_variant` / `switch.delete_key` /
   `switch.info` (params docs, tests, plug-in policy entry). FORMAT_VERSION 8 (v7 reads;
   every new field is a default).

## Live-gate corrections

* The fixtures' first attempts were caught by the gates or the saved JSON: a bare
  `pt.fPos = v` write moves a point but never keys it (verified in the saved JSON — zero
  channels) — the keying call is `M_Point:SetPos(vec, frame)` plus
  `moho:NewKeyframe(CHANNEL_POINT)`, and `pt.fAnimPos` is the channel.
* The scripting objects expose **no** `fSwitchKeys` member; the saved `switch_keys` channel
  is what `GroupLayer:SwitchValues()` returns, keyed per the official lm_switch_layer tool:
  `SetValue(layerFrame, name)` + `NewKeyframe(CHANNEL_SWITCH)`.
* Moho keys new points **Smooth** by default; the parity fixtures linearize explicitly so
  the gates measure exact interpolation. Three moving points moved too little for the
  static control to discriminate — the fixture moves eleven, and the gate then separates
  cleanly (F1 0.295–0.336 vs 0.214–0.293).

## Gates

* In-repo: eval tests (per-frame selection, compositing, point rebuilds, trim cutting,
  stroked text), file round trips (engine + text.moho/switch.moho through the native
  format), the whole corpus importing, panic-hunt, clippy, deny.
* Real machine (R2, Moho Pro 14.4, fixtures + CASES #18/#19): switch-keys.moho frame-by-frame
  F1 0.292/0.292/0.389/0.389 against the flipped-selector control's 0.226/0.226/0.256/0.256;
  point-anim.moho F1 0.295–0.336 against the stripped control's 0.214–0.293. The variant's
  −480 px layer offset is rebuilt to a −32 px residual.
